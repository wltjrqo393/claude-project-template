# zip-deliver

이 레포의 코드는 사내 환경으로 **zip 파일**로 옮겨진다. 아래 순서를 그대로 따른다.

## 1. 커밋 상태 확인
- zip은 `git archive`로 만들기 때문에 **커밋된 파일만** 들어간다.
- `git status --porcelain`이 비어 있지 않으면, 전달할 변경을 먼저 커밋한다.
  커밋하면 안 되는 파일(.env, 가중치, 로그)이 섞여 있으면 `.gitignore`에 추가하고 사용자에게 알린다.

## 2. CHANGES.md 갱신 후 커밋
- `CHANGES.md` 맨 위 항목에서 직전 전달의 `commit:` 해시를 찾는다.
  - 해시가 있으면 `git diff --name-status <해시> HEAD`로 변경 파일 목록을 뽑는다.
  - 없으면(첫 전달이면) "최초 전달 — 전체 파일"이라고 쓴다.
- 맨 위에 새 항목을 추가한다. `commit:` 줄은 이 시점에는 비워 두고(`commit: (zip 생성 시 기록)`), 아래 형식을 지킨다.
  ```
  ## <프로젝트명>_<YYYYMMDD>_v<N>
  - 요약: 한두 줄
  - 추가: path/a.py
  - 수정: path/b.py
  - 삭제: path/c.py
  - commit: (zip 생성 시 기록)
  ```
- CHANGES.md를 커밋한다.

## 3. zip 생성 + 검증
```bash
bash .claude/skills/zip-deliver/scripts/make_zip.sh
```
- 스크립트가 하는 일: 미커밋 변경이 있으면 중단 → `dist/<프로젝트명>_<YYYYMMDD>_v<N>.zip` 생성(N 자동 증가) → 금지 파일(.env, 가중치, 캐시 등) 검사 → 빈 디렉터리에 압축 해제 확인 → 내용물 목록과 커밋 해시 출력.
- 금지 파일이 발견되어 실패하면 원인을 고치고 다시 실행한다. 검사를 우회하지 않는다.
- 스크립트가 출력한 커밋 해시를 CHANGES.md 방금 만든 항목의 `commit:` 줄에 기록하고 커밋한다.
  (이 커밋은 문서만 바뀌므로 zip을 다시 만들 필요 없다.)

## 4. 전달
- 파일 전송 도구가 있으면 `dist/` 아래 zip을 사용자에게 보낸다. 없으면 경로를 알려준다.
- zip 파일 자체는 커밋하지 않는다 (`dist/`는 gitignore).
- 사용자에게는 짧게 보고한다: zip 파일명, 변경 요약(CHANGES.md 항목), 사내 환경에서의 설치/실행 명령(README 기준).
- push는 사용자가 요청할 때만 한다.
